# Auditoría de repositorio
1. Leer AGENTS.md, README, documentación arquitectónica, manifiestos y política de seguridad antes de editar.
2. Revisar rama, git status, archivos modificados y comandos realmente disponibles. No asumir que el árbol local está sincronizado.
3. Identificar componentes, límites de confianza, dependencias, CI, pruebas y despliegue.
4. Separar observaciones comprobadas, hipótesis y riesgos. No presentar prototipos como funciones validadas.
5. Entregar un mapa breve, prioridades P0/P1/P2, evidencia con rutas concretas y plan mínimo reversible.
6. No modificar archivos sin un encargo de implementación explícito.
